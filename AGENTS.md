# GHUB-X (crate `ghubx`)

G HUB-style control app for the Logitech G502 HERO (USB `046D:C08B`), Rust + egui 0.37.

## Commands

- Build: `cargo build` (debug) / `cargo build --release` (no console window, thin LTO)
- Tests: `cargo test` (77 tests, about 3 s: protocol decoding, palette, OSD render, game scan parsers, export/import, and engine behaviour through a fake input sink and device channel; nothing touches the mouse or injects input)
- Lint: `cargo clippy --all-targets` (keep it warning-free)
- Device probe (read-only): `cargo run --bin probe`
- Probe subcommands: `probe ghub-status` (is `lghub_agent.exe` running), `probe ghub-close` / `probe ghub-start` (same `win.rs` calls as the UI buttons), `probe takeover-test` (WRITES to the mouse: host mode, spy map, DPI, rate, LEDs, then releases to onboard; exit 2 if G HUB's agent or any `ghubx.exe` is running, 0 only if every step passes), `probe release` (WRITES: stop spy, identity map, onboard mode; exit 2 if G HUB's agent is running)
- `probe listen [secs]` (read-only): prints 0x8110 button events, also next to a running GHUB-X or G HUB
- Env `GHUBX_CONFIG_DIR`: base dir instead of `%APPDATA%` (config is `<dir>\ghubx\config.toml`); point `--shot` runs at a frozen copy so live config changes can't alter screenshots
- Shot flags (in memory only): `--theme <id>`, `--accent <RRGGBB>`, `--follow-lighting`, `--switch-to <id>` (switches theme on frame 10 via the same path as the Appearance tiles)
- `probe osd-png <out.png> dpi <value> <levels> <active> | profile <name> [--theme id] [--scale f]` writes the OSD as a PNG; `probe osd dpi <value> <levels> <active> | profile <name>` shows it on screen for ~2 s
- `probe export-theme <idx> <file>` / `probe import-theme <file>` (custom themes as `.ghubxtheme`; never writes the config)
- `probe game-sens` (read-only: CS2 / Valorant sensitivity and half-turn counts)
- `probe onboard` (READ-ONLY dump of the mouse's on-board profile directory; refuses while G HUB runs)
- `probe cache-sync` (writes the saved copy), `probe export-app <idx> <file>` / `probe import-app <file>` (never writes the config), `probe ghub-autostart` (read-only), `probe save-dialog`
- `probe games` lists installed games (name | source | folder | G HUB id | commands with a key combo); `probe pick-exe` opens the native exe picker and prints the result
- Scripted UI: `ghubx.exe --dev --script <file>` (needs `GHUBX_CONFIG_DIR`; exit 2 otherwise, exit 3 on a malformed line) runs the real UI off-screen at (-32000,-32000) with synthetic egui input, one script line per frame, no tray/mutex/sync. Commands: `wait <ms>`, `move x y`, `click x y`, `rclick x y`, `dclick x y`, `drag x1 y1 x2 y2`, `scroll x y dy`, `key <EguiKeyName>`, `text <string>`, `shot <png>`, `quit` (normal exit, config saved). Observer mode never installs the wheel hook or enables scroll acceleration. `python tools/ui_test.py [name ...]` runs 21 click scenarios (each starts from `tools/ui_seed_config.toml` in a fresh folder under `%TEMP%\ghubx_ui_test`, asserts on the saved config / pixels); ~80 s. Coordinates assume a 1024x768 window at 100% scale. `add_detected_game` and `use_game_sensitivity` need this PC's Counter-Strike 2 install and its sensitivity of 0.51
- Dev instance: `ghubx.exe --dev` needs `GHUBX_CONFIG_DIR` (else exit 2), uses mutex `Local\GHUBX-single-instance-dev`, tray class `GHUBX_TRAY_DEV`, tooltip "GHUB-X (dev)"; `engine::set_observer(true)` (set for `--dev` and `--shot`) means it never takes control, never closes/starts G HUB and never writes the on-board slot; autostart toggles are disabled. Safe to run next to the live app for scripted tests
- Flags: `--minimized` (start hidden in the tray), `--shot <page> <out.png>` (no mutex, no tray)
- Regression check for any UI change: `python tools/shots.py render <dir>` before and after (all 28 pages from `tools/ui_seed_config.toml`; two renders of the same code are pixel-identical), then `python tools/shots.py diff <before> <after> 0`: only the pages you meant to change may differ. Add `--theme <id>` to render another theme. New `--shot` pages must be added to `PAGES` in `tools/shots.py`.
- Page screenshots without touching the mouse: `target/debug/ghubx.exe --shot <page> <out.png>`
  pages: home, dropdown, assign, assign2, gshift, select, keys, actions, macro, macroedit, sens, light, fixed, devset, profiles, appdetail, settings, sleep (settings with lighting sleep on), appearance, themeedit (theme editor open on a sample draft), mythemes (two sample custom themes), p180game (ACTIONS with the Perfect 180 game-sensitivity line), macrorec (macro editor recording), onboard (Device Settings with sample on-board slots), ghub (Settings > G HUB tab), addgame (Profiles with the add form open), gamecmds (Assignments > COMMANDS for an in-memory Counter-Strike 2 app), diag
- Rebuilding the release while the app runs (it usually controls the user's mouse): rename `target/release/ghubx.exe` to `ghubx.old.exe` (Windows allows renaming a running exe), `cargo build --release`, post `WM_APP+3` to the `GHUBX_TRAY` window (clean quit: the mouse goes back to on-board mode), start the new exe (add `--minimized` if the old window was hidden), check with `probe` that mode is 2 again, delete `ghubx.old.exe`. About 0.5 s without control.
- Never `taskkill /F` a controlling instance: the mouse stays in host mode with its remapped buttons muted. If that happens, `probe release` puts it back in on-board mode.

## Layout

- `src/hidpp.rs` HID++ 2.0 transport (short 0x10 on usage 0x0001, long 0x11 + all input on usage 0x0002)
- `src/device.rs` G502 operations (DPI 0x2201, report rate 0x8060 in ms, onboard 0x8100, LEDs 0x8070, button spy 0x8110)
- `src/profile.rs` data model (apps -> profiles -> base/G-Shift layers, DPI table, lighting, macros) + onboard sector CRC
- `src/engine.rs` takeover policy (only when G HUB's `lghub_agent.exe` isn't running), spy bitmap -> actions
- `src/io.rs` HID owner thread; `src/win.rs` SendInput, foreground app, G HUB process control, autostart, wheel hook
- Tray / background (`win.rs`, pure Win32): hidden top-level window (`WS_EX_TOOLWINDOW | WS_POPUP`, never shown, so it receives `TaskbarCreated` and `WM_ENDSESSION` broadcasts) of class `GHUBX_TRAY` on its own thread; `WM_ENDSESSION` (wParam != 0) runs the quit path so a shutdown/logoff releases the mouse; mutex `Local\GHUBX-single-instance` (a second launch finds the tray window with `FindWindowW` (not message-only), posts `WM_APP+2` and exits). Messages: `WM_APP+1` tray callback (left click/double click show, right click menu Open/Quit), `WM_APP+2` show main window, `WM_APP+3` quit. Show/hide use raw `ShowWindow` (eframe runs no frames while hidden, so the engine/IO threads must never depend on the UI loop; `ui::spawn_stash` keeps the UiEvent channel drained while hidden). Shutdown is one function, `ui::Exit::run` (save config, engine Quit, wait IO thread, remove icon), used by `on_exit` and tray Quit. `win::tray_ready()` gates close-to-tray and `--minimized` hiding (no tray = window stays reachable). `--minimized` starts the window at (-32000,-32000), hides it after eframe's first frame and re-centres it on the work area. One icon: `win::app_icon_rgba(size)` (tray 32, window 64). Control watchdog: the IO thread's periodic refresh sends `EngineMsg::ControlLost` if the mouse left host mode while controlled; the engine retries after 1 s. Config: `general.close_to_tray` (default on), `general.start_minimized` (adds ` --minimized` to the autostart Run entry)
- `src/ghub_import.rs` imports `%LOCALAPPDATA%\LGHUB\settings.db` (copied to temp first)
- OSD (`src/osd.rs`): `render(kind, palette, scale)` is pure CPU (ab_glyph, premultiplied BGRA); `show(kind)` drives a layered, click-through, topmost, no-activate window (`GHUBX_OSD`) on its own thread (fade 100 ms, hold 1400, fade 300; monitor of the foreground window, DPI scaled). The engine calls it (`Engine.osd`) for DPI buttons and for profile changes while in control (`general.osd_dpi`, `general.osd_profile`). `general.dpi_flash` flashes both zones in `dpi_flash_color(level)` for 1.2 s (`flash_until`, `expire_flash`). Engine tests use `Engine.persist = false` and an injected `osd` closure; `set_observer` is a process-wide flag so engine tests run serially
- On-board profiles are read-only: `DevCmd::ReadOnboard` walks sector 0 and each directory sector one per IO pass (`io::OnboardJob`), results come back as `UiEvent::Onboard`; Device Settings shows `onboard_summary` per slot. Nothing here may call `write_sector`
- Macro editor: `MacroEditor` step methods (`set_delay`, `move_step`, `add_key/click/delay/text`) are pure and unit-tested; `+ TEXT` uses `win::char_key`; TEST sends `EngineMsg::TestMacro` (played once through the input sink); recording also takes mouse buttons inside the step list
- Engine input goes through `engine::Input` (`RealInput` forwards to `win::*`; tests inject a recorder), so button behaviour is unit-tested without touching the mouse
- Saved copy: `assets::sync_cache()` (background thread at startup of the app and `--dev`, never `--shot`) copies G HUB's fonts, device images, metadata and `applications.json` to `%LOCALAPPDATA%\ghubx\cache` (`GHUBX_CACHE_DIR` overrides). Loaders try the install first, then the copy; `GHUBX_NO_GHUB=1` pretends G HUB is not installed. Diagnostics shows each source (`assets::source`). Settings > G HUB also has the 'Start G HUB with Windows' row (`win::startup_approved` / `set_startup_approved`, StartupApproved\Run)
- Export/import: `profile::export_app` / `import_app` (`.ghubx` = TOML, `format = 1`), `Config::add_imported`; dialogs `win::pick_file` / `save_file`
- Game sensitivity (`games::game_sensitivity`): reads CS2's `cs2_user_convars_0_slot0.vcfg` and Valorant's `RiotUserSettings.ini` (read-only, newest file) to calibrate Perfect 180 (`180 / (yaw x sens)`); used when adding a detected game and by the 'USE MY ... SENSITIVITY' line in the Perfect 180 box. `--shot` uses a fixed sample, never the real files
- Games (`src/games.rs`): G HUB's `applications.json` is read at runtime (`games::preload()` at startup, `db()` / `db_blocking()`), never copied into the repo. `scan()` finds installed games (Steam acf, Epic items, Riot yaml, registry rules, GOG, Ubisoft; the last three are unit-tested only). `AppEntry.dir` (install folder) matches the foreground *process path* (`win::foreground_path`, `Status.foreground_path`); an `exe` match beats a `dir` match, the longest `dir` wins. `AppEntry.ghub_id` adds the game's commands (as `Assignment::Shortcut`) to Assignments > COMMANDS. Profiles > ADD GAMES & APPS lists detected games and has BROWSE (`win::pick_exe`, `GetOpenFileNameW`)
- Perfect 180: presets `P180_GAMES` (indices 0..=3 are stable; `P180_CUSTOM` = 3, shown last via `P180_ORDER`), `Extras.p180_angle`, per-profile `Profile.turn: Option<TurnCal>` (`turn_for`, `turn_counts`)
- `--shot` runs ignore live spy button events (the live app's presses would leak into screenshots) and the shot clock advances 0.05 s/frame once the page is ready so popups finish fading in
- Themes: `src/ui/palette.rs` holds `Palette` (global `pal()` / `set_palette`), 5 presets (ids `ghub-dark`, `ghub-light`, `razer-green`, `midnight`, `ember`; `ghub-dark` is the original G HUB look verbatim), `n(level)` neutral ramp, `ink(alpha)`, `with_accent`, `resolve(&Appearance, lighting_accent)`. No `Color32` literals in `src/ui` except images/renders, the colour picker, LEDs, posters, shadows and the close-button red. `App::ui` recomputes the palette every frame (config `[appearance] theme/accent/follow_lighting`; follow-lighting uses the logo zone) and restyles when it changes. Settings > Appearance is tab 1. User-made themes: `Appearance.custom: Vec<CustomTheme>` (bg / surface / text / accent; `Appearance.theme` may hold a `custom-...` id), `palette::custom_palette` derives everything else, `palette::contrast` gives the WCAG ratio; MY THEMES tiles, IMPORT/EXPORT/EDIT and the editor (live preview: the whole window uses the draft palette while it is open; it is dropped whenever the route leaves Appearance) live in `src/ui/themes.rs`; the colour picker in `light.rs` takes its state (`PickerState`) as a parameter
- `src/ui/` G HUB look: fonts from `C:\Program Files\LGHUB\resources\app.asar`, renders + hotspots from `C:\ProgramData\LGHUB\depots\*\g502_hero`

## Rules

- Never write spy map / host mode while G HUB is running (it owns the mouse); `--shot` forces `take_control = false`.
- Don't ship Logitech assets; they are read from the local G HUB install at runtime.
- `write_sector` (flash) exists but is not exposed in the UI; verify on hardware before wiring it up.
- Config: `%APPDATA%\ghubx\config.toml`.
- Live check with G HUB closed: `probe ghub-close`, then `probe takeover-test` (all 8 steps passed on 2026-11-21). `probe release` is the rescue command (mouse back to onboard mode). Onboard mode on this mouse is 3200 DPI, so the pointer speeds up whenever no software controls it.
